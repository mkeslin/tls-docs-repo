# Customer success

**Phase:** Expand  
**Desired outcome:** Ensure adoption

## Inputs

Live customer (post-hypercare / after [Deliver → Expand handoff](../../sops/expand/deliver-to-expand-handoff.md))

## Outputs

Healthy customer (scored band + next check-in date)

## Owner

**Expand owner** (today: Fugate)

## Target process

[Customer success check-in](../../sops/expand/customer-success-check-in.md) — cadence by segment; health bands Healthy / Watch / At-risk.

| Segment | Cadence |
|---------|---------|
| New post-hypercare | Day 30 → 60 → 90, then quarterly if Healthy |
| Healthy / steady | Quarterly |
| Watch | Often monthly |
| At-risk | Monthly (or tighter) + next action ≤ 14 days |

## Tooling

Pipedrive (activity SoR) · Hub Expand Desk (coaching + checklists)

## Capacity (today)

50–75 agencies

## Cycle time

See cadence table (not a single “quarterly for all”)

## Maturity

**2 / 5 — Documented** (target-state SOPs; execution still founder-led)

| Score | Meaning |
|------:|---------|
| 1 | Founder-driven |
| 2 | Documented |
| 3 | Standardized |
| 4 | Automated |
| 5 | Scalable |

## What would break first?

Cadence slips without a living Pipedrive next-touch date; At-risk without a ≤ 14-day action

## Continuous improvement (10x ideas)

| Lens | Idea |
|------|------|
| Reduce / Simplify | Reactive check-ins |
| Standardize | Success cadence (done in SOP) |
| Automate | Health scoring from ticket/usage data |
| Delegate | Customer Success |
| Scale | Dedicated CSM team |
