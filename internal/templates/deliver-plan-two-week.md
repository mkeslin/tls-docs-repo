# Two-week deliver plan

**Document type:** Template  
**Status:** v0.1  
**Audience:** Internal — Deliver  
**Related:** [Implementation lifecycle](../sops/deliver/implementation-lifecycle.md) · [Implementation workspace standard](../sops/deliver/implementation-workspace-standard.md) · [Deliver SOPs](../sops/deliver/README.md) · [Go-live](../sops/deliver/go-live.md) · [Hub Deliver Desk](../backlog/design/hub-deliver-desk.md) · [Hub epic plans](../backlog/design/hub-epic-plans.md)

Copy the **blank template** into Hub (Home → Plans → Deliver) or working notes for a specific period. Do not store completed personal plans in GitBook unless leadership wants a historical example retained below.

**What good looks like:** outcomes tied to phase exits and go-live readiness, named agencies with a clear phase and next action, calendar blocks for customer-facing work, and a Friday check-in that proves workspace hygiene—not vibe updates.

**System of record:** The per-customer [implementation workspace](../sops/deliver/implementation-workspace-standard.md) remains engagement SoR. This plan is the Deliver owner’s two-week coaching artifact; executable day work also lives on Hub notecards.

## Example (illustrative)

*Example only — replace dates, agency names, and targets for the real period.*

### Deliver owner — implementation plan (2 weeks)

**Period:** Mon Jul 27 – Fri Aug 7, 2026  
**Focus:** Go-live readiness + one migration validation push  
**Engagement SoR:** Implementation workspace  

#### KPIs (end of 2 weeks)

| KPI | Target |
|-----|--------|
| Engagements with a clear next action dated in the workspace | **100% of named priorities** |
| Phase exits completed (or explicitly N/A with reason) | **2** |
| Go-lives / cutovers this period | **1** |
| UAT / training / customer sessions completed | **3** |
| Hypercare exits / Operate handoffs | **1** |

#### Week 1 — Unblock + validate

| Day | Block | Work |
|-----|-------|------|
| Mon | 60 min | Portfolio review: phase status on named priorities; escalate blockers. |
| Tue | 90 min | Migration validation session (agency A) — log issues in workspace. |
| Wed | 60 min | Config / training prep for agency B go-live window. |
| Thu | 90 min | Customer working session (agency B) — exit criteria checklist. |
| Fri | 45 min | Scorecard + risk notes; confirm Week 2 cutover owners. |

#### Week 2 — Cutover + hypercare

| Day | Block | Work |
|-----|-------|------|
| Mon | AM | Go-live readiness gate (agency B) — decision record if used. |
| Tue | **Cutover** | Agency B go-live support; same-day workspace updates. |
| Wed | 60 min | Hypercare triage for agency B; open defects with owners. |
| Thu | 60 min | Agency C phase exit (e.g. Infrastructure or Configuration). |
| Fri | 45 min | Check-in artifact + draft next two-week plan. |

#### Named priorities (keep moving in parallel)

- Agency B — Phase 7 Go live — cutover Tue — decision owner named  
- Agency A — Phase 3 Data migration — validation defects closed  
- Agency C — Phase 2/4 — next exit criteria dated  

#### Definition of done (Friday check-in)

1. Counts vs goals (phase exits, go-live, sessions, hypercare)  
2. Named priorities each have phase + dated next action  
3. Blockers escalated  
4. Next week’s first customer-facing block on the calendar
